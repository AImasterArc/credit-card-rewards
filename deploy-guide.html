部署到 GitHub Pages，裝到 iPhone 16 Pro

全程免費。約 10 分鐘。完成後得到一個網址，用 Safari 加到主畫面就像原生 App。

先釐清：GitHub 只存放「程式碼」。你的卡片與消費資料只存在 iPhone 本機，不會上傳，所以 repo 設為公開也不會洩漏個資。GitHub Free 的 Pages 只支援公開 repo。

0前置確認

  • 已有 GitHub 帳號（註冊）。
  • 電腦已裝 Git 與 Node.js（你的環境已有）。
  • 本機先驗證能過：
cd C:\Users\f2289\Arc\AI_Code\credit_card
npm ci
npm test
npm run build

1在 GitHub 建立空 repo

  1. 開啟 github.com/new。
  2. Repository name 填 credit-card-rewards（名字會成為網址的一部分）。
  3. 選 Public。
  4. 不要勾選 README / .gitignore / License（保持空的，避免推送衝突）。
  5. 按 Create repository，複製頁面上的 HTTPS 網址，例如 https://github.com/你的帳號/credit-card-rewards.git。

2把專案推上去

在專案資料夾的 PowerShell：

git init -b main
git add .
git commit -m "feat: credit card rewards PWA"
git remote add origin https://github.com/你的帳號/credit-card-rewards.git
git push -u origin main
  • 第一次推送會跳出 GitHub 登入視窗（Git Credential Manager），登入授權即可。
  • 若 commit 提示「Please tell me who you are」： 
    git config --global user.name "你的名字"
git config --global user.email "你的GitHub信箱"
  • .gitignore 已排除 node_modules、dist、E2E 截圖，不會被推上去。
用 GitHub CLI 一行搞定（可選） 
gh auth login
gh repo create credit-card-rewards --public --source . --push

3啟用 GitHub Pages（Actions 部署）

  1. 進入 repo → Settings → 左側 Pages。
  2. Build and deployment → Source 選 GitHub Actions（不是 Deploy from a branch）。
這步一定要做。沒設定的話 workflow 的 deploy 步驟會失敗，訊息是 Get Pages site failed 或 HttpError: Not Found。設定完到 Actions 頁，對失敗的 run 按 Re-run all jobs 即可。

4等待自動建置

  1. 進入 repo 的 Actions 分頁，會看到 Deploy to GitHub Pages 在跑。
  2. 流程：安裝 → 跑單元/整合測試 → 建置 → 上傳 → 部署，約 1–2 分鐘。
  3. 全部綠色打勾後，點 deploy 工作中的連結，或到 Settings → Pages 看網址：
https://你的帳號.github.io/credit-card-rewards/
之後每次 git push 到 main 都會自動重新部署；測試沒過就不會上線。

5在 iPhone 16 Pro 安裝

務必用 Safari 開啟。資料儲存是依「網址 + 瀏覽器」隔離的：在 Safari 試用的資料，不會出現在主畫面版 App。所以請先安裝，再開始輸入資料。
  1. 用 Safari 開啟上面的網址。
  2. 點底部工具列的 分享 按鈕（方框加向上箭頭）。
  3. 往下滑，點 加入主畫面。
  4. 確認名稱「刷卡回饋」，點右上角 加入。
  5. 回到主畫面，點新出現的圖示開啟——不會有網址列，全螢幕顯示並避開 Dynamic Island 與底部 Home 指示條。
找不到「加入主畫面」？
  • 分享選單最底部點 編輯動作，把「加入主畫面」加入常用項目。
  • 在 iOS 的 Chrome / Edge 也可以（iOS 16.4 以上），但建議 Safari 最穩。
  • 若分享按鈕是灰的，確認不是在「私密瀏覽」分頁。

6第一次使用建議

  1. 從主畫面圖示開啟 App。
  2. 設定 → 持久化儲存 → 啟用，要求系統不要自動清除資料。
  3. 卡片庫 → 新增卡片，設定結帳日；先建一條「一般消費」規則（超過上限的部分會改用它計算），再加指定類型規則。
  4. 點底部 ＋ 記第一筆消費，確認推薦與總覽的 Bar 正常。
  5. 設定 → 匯出備份，在分享選單選「儲存到檔案」→ iCloud Drive。

7資料安全：什麼時候會消失？

情況資料
關閉 App、手機重開機✅ 保留
更新 App（推送新版本）✅ 保留（IndexedDB 不受影響）
主畫面版 App 長時間沒開✅ 一般保留（主畫面 Web App 不受 Safari 7 天規則限制）
從主畫面刪除 App 圖示❌ 資料一併刪除
設定 → Safari → 清除歷史記錄與網站資料⚠️ 可能清除，操作前先備份
換新手機需用備份檔「從備份匯入」還原
App 會在「有資料且超過 7 天沒備份」時於總覽顯示提醒橫幅。建議每月結帳後匯出一次。

8更新 App

git add .
git commit -m "fix: ..."
git push

Actions 部署完成後，在手機完全關閉 App（上滑關閉）再重新開啟，Service Worker 會在背景下載新版，可能需要再開啟一次才會套用。資料不受影響。

9疑難排解

症狀原因 / 解法
網址開啟後空白頁，Console 出現 404 的 js/cssbase path 不符。Repo 名稱若不是預設，workflow 會自動用 /${{ github.event.repository.name }}/。若 repo 名稱是 你的帳號.github.io，把 .github/workflows/deploy.yml 的 VITE_BASE 改成 /。
Actions 的 npm ci 失敗確認 package-lock.json 有一起 commit。
Actions 的 npm test 失敗本機先跑 npm test 看哪個案例失敗；測試沒過不會部署。
Deploy 步驟 Not Found步驟 3 的 Source 沒選 GitHub Actions。
推新版後手機還是舊版完全關閉 App 再開兩次；仍不行則 Safari 開網址重新整理一次。
App 圖示是空白 / 預設需重新「加入主畫面」；圖示由 npm run icons 產生並放在 public/。
匯出沒跳分享選單需在 HTTPS 的主畫面版執行；區網 http 測試會改走下載。
輸入框聚焦時畫面放大已將輸入框字級設為 16px 避免；若仍發生請回報機型與頁面。

★本機在手機上預覽（開發用，可選）

npm run dev

終端機會顯示 Network: http://192.168.x.x:5173/。手機與電腦在同一個 Wi-Fi，用 Safari 開該網址即可。此模式是 HTTP，Service Worker 與持久化儲存不可用，僅供看版面。

在電腦瀏覽器看：視窗寬度 ≥ 640px 時，畫面會以 402 × 874（iPhone 16 Pro）圓角外框呈現。
